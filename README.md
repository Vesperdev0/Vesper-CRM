# VESPER CRM — production-ready starter

VESPER is an outreach CRM for a two-person sales/outreach team. It includes the core UI, pipeline, company records, activity history, tasks, calendar surface, light/dark mode, search, and a Google Calendar OAuth integration.

## Stack
- Next.js + React + TypeScript
- Supabase Auth + Postgres + Row Level Security
- Google Calendar API / OAuth 2.0

Supabase provides the auth/session/database layer; Google Calendar is connected per user. Google Calendar event creation requires OAuth calendar write access and can include Google Meet conference data.

## 1. Install
```bash
npm install
cp .env.example .env.local
npm run dev
```

## 2. Supabase
Create a Supabase project, then run `supabase/schema.sql` in the SQL editor.

Create two users in Authentication > Users. Disable email confirmation if you want simple username/password-style sign-in. The VESPER login accepts either the user's full email or the username prefix and maps a username such as `shelwin` to `shelwin@vesper.local`.

Set:
- NEXT_PUBLIC_SUPABASE_URL
- NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY

The service-role key is intentionally not required by the browser app. If you later add privileged server jobs, store it only server-side.

## 3. Google Calendar
In Google Cloud Console:
1. Create/select a project.
2. Enable Google Calendar API.
3. Configure the OAuth consent screen.
4. Create a Web application OAuth client.
5. Add the redirect URI:
   `http://localhost:3000/api/calendar/callback`
6. Put the client ID/secret in `.env.local`.

For production, change the redirect URI to your HTTPS deployment URL.

## 4. Production deployment
Deploy the Next.js app to Vercel or another Node-compatible host, configure the same environment variables, and add the production callback URI in Google Cloud.

## Important
The repository is functional, but you still need to connect your own Supabase and Google Cloud projects. Those credentials cannot be generated by the application itself.
